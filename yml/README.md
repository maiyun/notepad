# Update metadata examples

These files illustrate stable-channel update metadata for Windows NSIS, macOS ZIP, and Linux AppImage builds. They contain placeholder hashes, sizes, versions, and filenames and cannot be used for a real release. Publish the metadata generated by `clickgo --native` together with its matching packages and auxiliary files instead.

| Field | Value |
| --- | --- |
| `version` | The new desktop version from the root `package.json.version`. |
| `files[].url` | The exact package filename, or a full HTTPS download URL when using a generic server. |
| `files[].sha512` | Base64-encoded SHA-512 of the package bytes, not a hexadecimal string. |
| `files[].size` | Package size in bytes. |
| `releaseDate` | ISO 8601 release timestamp. |

To inspect a package's size and hash:

```sh
node -e "const fs = require('node:fs'); const crypto = require('node:crypto'); const data = fs.readFileSync(process.argv[1]); console.log('size:', data.length); console.log('sha512:', crypto.createHash('sha512').update(data).digest('base64'));" "path/to/package"
```

## GitHub Releases

The current `build.publish` configuration uses GitHub Releases. Attach the generated metadata, packages, and auxiliary files to the corresponding published release. Use the generated asset filenames; package URLs are resolved within that release. There is no need to configure a separate package download URL in Notepad.

## Your own HTTPS server or CDN

Replace `build.publish` in the root `package.json` with:

```json
"publish": {
  "provider": "generic",
  "url": "https://updates.example.com/notepad/"
}
```

The domain above is an example. Upload the generated metadata and matching packages to your actual update directory. Windows requests `latest.yml`, macOS requests `latest-mac.yml`, and Linux x64 requests `latest-linux.yml`. Other architectures or release channels may use different names; keep the generated names and publish metadata matching each architecture.

For a package in the same directory, `files[].url` can be its filename. If packages are hosted separately, it can be a full address such as `https://cdn.example.com/notepad/ClickGo-Notepad-Setup-1.1.0.exe`. Keep the hash and size unchanged unless the package bytes change. Upload packages before replacing metadata so clients cannot detect a version whose package is not yet available.

Windows updates use the NSIS installer, not the portable executable. macOS requires signing and a ZIP update artifact. See the [electron-updater guide](https://www.electron.build/v26/docs/features/auto-update/) for platform requirements.
